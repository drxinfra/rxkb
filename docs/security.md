# rxkb: безопасность

Документ для тех, кто решает, можно ли подключать rxkb к своим агентам, и для тех, кто держит сервер: что уходит на сервер, что он хранит, как он защищён как публичный сервис. Выкладка описана в [deploy.md](deploy.md).

## Коротко

- Сервер только читает: инструментов, которые что-то меняют, нет. Аннотации всех инструментов `readOnlyHint: true`, `openWorldHint: false`.
- Вход не нужен, учёток и ключей нет, cookies нет. Сервер не знает, кто его спрашивает.
- Аргументы вызовов (строки логов, запросы, параметры расчётов) не сохраняются ни в файлах, ни в журнале. Журнал сервиса пишет одну строку метаданных на запрос.
- Сервер не открывает исходящих соединений: всё, что он отвечает, лежит в `kb.json`, собранном из исходников сайта. В systemd исходящая сеть закрыта (`IPAddressDeny=any`, разрешён только localhost).
- Данные в ответах — открытые материалы drxinfra.ru: те же статьи, справочник и калькуляторы, что видит любой посетитель сайта.

## Что уходит на сервер

| Инструмент | Что передаёт агент |
|---|---|
| `find_error` | строку лога или текст ошибки (сервер проверяет первые 16 000 символов) |
| `search_site` | слова запроса |
| `get_article` | id или адрес статьи |
| `size_rx`, `size_ai` | числа и значения из списков: пользователи, документы, модель, сервер |
| `upgrade_checklist` | номера отмеченных пунктов и до 40 символов версий и окна работ |
| `security_self_check` | ответы y, p, n, u на вопросы по номерам |

Самое чувствительное здесь строка лога: в ней бывают имена серверов, логины, адреса, иногда токены. Серверу нужна только сама ошибка, поэтому инструкция сервера (поле `instructions`) и описание `find_error` просят агента вычищать такое до отправки. Сервер строку не хранит, но она проходит через сеть и через ИИ-клиента пользователя, поэтому правило остаётся в силе.

## Что пишется в журналы

| Где | Что | Срок |
|---|---|---|
| журнал сервиса (journald, `journalctl -u rxkb`) | метод JSON-RPC, имя инструмента, имя и версия клиента из `clientInfo`, код ответа, размеры запроса и ответа, время. Адреса клиента и аргументов нет | по настройкам journald сервера |
| журнал доступа nginx `drxinfra.mcp.log` | формат `anon` сайта: адрес с обнулённым последним октетом (IPv6 до второй группы), время, `POST /mcp`, код, размер, Referer, User-Agent. Тела запроса нет | ротация журналов nginx сайта, отдельно от статистики посещаемости |
| журнал ошибок nginx | отказы лимитов для `/mcp` пишутся уровнем `warn` и при уровне журнала `error` не пишутся вовсе | — |

Аргументы не попадают в журнал и при сбое: паника обработчика пишет только стек, значение паники (оно может цитировать запрос) не пишется. Журнал ошибок HTTP-сервера Go отключён: он печатает мусор сканеров.

## Защита публичного сервиса

| Что | Где | Значение |
|---|---|---|
| Частота запросов с адреса | nginx `mcp_req` | 2 в секунду, всплеск 30, сверху общий лимит сайта 30 в секунду |
| Частота запросов с адреса | сервис | 2 в секунду, всплеск 30 (`RXKB_RATE`, `RXKB_BURST`), таблица адресов не больше 50 000 |
| Одновременные соединения с адреса | nginx `mcp_conn` | 8 |
| Одновременные запросы всего | сервис | 16 (`RXKB_MAX_CONCURRENT`), остальные ждут до 2 с и получают 503 |
| Размер запроса | nginx и сервис | 128 КБ (`client_max_body_size`, `RXKB_MAX_BODY`, `MaxRequestBodyBytes` SDK) |
| Длина аргументов | схемы инструментов | строка лога до 20 000 символов, запрос поиска до 300, id до 300, числа в границах формы сайта |
| Время | nginx и сервис | заголовки 5 с, тело 15 с, ответ 30 с на прокси; вызов инструмента 5 с; расчёт в интерпретаторе JavaScript прерывается через 1 с |
| Длина ответа | сервис | до 40 000 символов, статья до 30 000, разделы статьи в `find_error` до 2000 |
| Лишние параметры | схемы инструментов | `additionalProperties: false`: неизвестный параметр — ошибка, а не тихое игнорирование |
| Пути из ввода | сервис | нет: id статьи ищется в словаре в памяти, к файлам ввод не прикасается; сервис читает только свой `kb.json` |

Отказ лимита nginx в журнал ошибок не пишется, поэтому джейл fail2ban `nginx-limit-req` на `/mcp` не срабатывает. Так сделано намеренно: несколько агентов из одного офиса за NAT не должны закрыть себе весь сайт на час. Флуд на `/mcp` отбивается кодом 429 на уровне nginx, до сервиса он не доходит.

Сервер работает без сессий (режим Stateless SDK, протокол 2026-07-28): на сервере нет состояния клиентов, которое можно раздуть, нет долгих потоков событий, каждый POST отвечает JSON и закрывается. GET и DELETE на `/mcp` отвечают 405, браузер получает переадресацию на страницу о сервере.

CORS открыт (`Access-Control-Allow-Origin: *`): данные публичные, учётных данных и cookies нет, поэтому вызов из браузерного клиента ничего не раскрывает. Защита SDK от DNS rebinding для localhost выключена: сервис стоит за nginx, все запросы приходят с 127.0.0.1 с публичным `Host`, а защищать на нём нечего — у него нет ни данных пользователя, ни прав.

## Процесс и образ

- systemd: `DynamicUser=yes` (пользователь без входа и без своих файлов), `ProtectSystem=strict`, `ProtectHome`, `PrivateTmp`, `PrivateDevices`, `NoNewPrivileges`, пустой `CapabilityBoundingSet`, `RestrictAddressFamilies`, `SystemCallFilter=@system-service`, `MemoryDenyWriteExecute`, `IPAddressDeny=any` с `IPAddressAllow=localhost`, `MemoryMax=256M`, `CPUQuota=100%`: сайт на том же сервере важнее. Файл: [deploy/rxkb.service](../deploy/rxkb.service).
- Образ Docker из `scratch`, пользователь 65532, внутри только бинарник, лицензия и корневые сертификаты; база монтируется томом только для чтения.
- Бинарник статический (`CGO_ENABLED=0`), сборка `-trimpath`. CI прогоняет trivy по бинарнику и по образу и падает на HIGH и CRITICAL, у которых есть исправление (`hack/vulncheck.sh`).
- JavaScript в сервисе — только модель калькулятора из репозитория сайта, собранная в базу при выкладке. Из запроса в интерпретатор попадают числа и строки из перечня схемы, своего кода клиент передать не может. У интерпретатора нет доступа к файлам, сети и функциям Go.
- Шаблоны справочника ошибок компилируются движком RE2 (линейное время на любом вводе). Шаблон, который RE2 не понимает, идёт в regexp2 с тайм-аутом 50 мс и ограниченным стеком возвратов.

## Если нашли уязвимость

Напишите на почту с сайта drxinfra.ru или откройте приватное сообщение о безопасности в репозитории (Security → Report a vulnerability). Публичный issue для уязвимостей не открывайте.
